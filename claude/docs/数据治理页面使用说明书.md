1. 浏览器打开 `http://127.0.0.1:8099/edge`，用管理员账号（本实例 `devadmin`）登录。

## 2. Tab一：策略管理

> 策略 = 一组**可复用的抽样/脱敏规则**。一次配置，之后提交任务时选「按策略」即可复用；任务执行时会对策略做**全快照**，策略后续修改不影响已执行任务的可追溯性。

### 2.1 顶部筛选与列表

- **类型下拉**：全部类型 / 抽样 / 脱敏 / 抽样+脱敏 —— 按策略类型过滤。
- **策略名称搜索框**：输入名称关键字回车搜索。
- **「新建策略」按钮**：打开新建表单（见 2.2）。

列表列：`策略`（名称 + 类型标签）、`抽样方法`、`脱敏列`（数量）、`创建人`、`更新时间`、`操作`（编辑/删除）。

### 2.2 新建策略 —— 逐字段填写说明（点击「新建策略」）

> 以下每个字段都以银行数据表给出**可照抄**的示例。

**① 策略名称**（必填）
- 给策略起一个能看懂的名字。
- 示例：`手机号与账号掩码策略`、`按风控等级分层抽样`、`客户信息脱敏+抽样`。

**② 描述**（选填）
- 一句话说明策略用途。
- 示例：`对 gov_bank_sample 的手机号/身份证做掩码，账号哈希`。

**③ 策略类型**（必填，三选一）
- **抽样**：只做抽样，不做脱敏（结果表保留真实数据，**不可在页面查看结果**）。
- **脱敏**：只做脱敏，不抽样（100 行全部保留）。
- **抽样+脱敏**：先抽样、后脱敏（最常用，结果表可直接在页面查看）。
- 示例：选 `抽样+脱敏`。

**④ 抽样方法**（策略类型含"抽样"时可选，否则留空）
| 选项 | 含义 | 适用场景 |
|---|---|---|
| `随机抽样 RANDOM` | 从 100 行中随机抽取 N 条（支持 seed 复现） | 快速取子集 |
| `等距抽样 SYSTEMATIC` | 按步长等距取 N 条 | 均匀覆盖 |
| `分层抽样 STRATIFIED` | 按指定列（如 `category` A/B/C）分层，每层各取若干 | 保证各风控等级都有样本 |
| `整群抽样 CLUSTER` | 按某列整群抽取，或按连续块抽取 | 按开户行/日期整块取 |

- 示例：选 `分层抽样`（配合下面抽样参数按 `category` 分层）。

**⑤ 抽样参数 (JSON)**（选填；抽样方法必填时的关键配置）

不同抽样方法对应的参数（照抄即可）：

| 方法 | 参数 JSON 示例 | 效果 |
|---|---|---|
| RANDOM | `{"count":5}` 或 `{"count":5,"seed":1}` | 随机取 5 条；同 seed 两次结果一致（可复现） |
| RANDOM | `{"ratio":0.1}` | 按比例取 100×10%=10 条 |
| SYSTEMATIC | `{"count":8}` | 等距取 8 条 |
| STRATIFIED | `{"strataColumns":["category"],"count":1}` | 按 `category`（A/B/C）分层，每层取 1 条 → 共 3 条 |
| STRATIFIED | `{"strataColumns":["category"],"ratio":0.5}` | 每层取 50% |
| CLUSTER | `{"clusterColumn":"category","count":1}` | 整群：随机选 1 个类别（如 A），取该类别全部 → 约 1/3 |
| CLUSTER | `{"blockSize":2,"count":3}` | 连续块：从 100 行中取 3 个连续 2 行的块 → 6 条 |

- 示例（分层）：`{"strataColumns":["category"],"count":1}`

**⑥ 脱敏列配置 (JSON)**（策略类型含"脱敏"时必填）

格式是 JSON 数组，每个元素一条规则：`{"column":"列名","method":"方法","params":{...}}`。

| 方法 | 参数 | 效果示例 |
|---|---|---|
| `MASK` 掩码 | `{"keepLeft":"3","keepRight":"4"}`（默认即可不写） | `18639416835` → `186****6835`；身份证 `110101197012078251` → `110*******8251` |
| `REPLACE` 替换 | `{"value":"REDACTED"}` | 整列替换为固定值（适合姓名/类别） |
| `REPLACE` 映射 | `{"mapping":"{\"A\":\"高\",\"B\":\"中\",\"C\":\"低\"}"}` | 精确匹配替换 |
| `HASH` 哈希 | `{"salt":"zgz-2026"}`（盐可选） | SHA-256 加盐，不可逆（适合账号/身份证） |
| `ROUND` 取整 | `{"digits":"2"}` | `467101.16` → 保留小数；`{"digits":"0"}` → `467101` |
| `CLEAR` 置空 | 无参数 | 列全部清空（适合备注） |
| `CLEAR` 删列 | `{"mode":"drop"}` | 整列从结果表中删除 |

- 示例（手机号+身份证掩码、账号哈希、备注清空、余额取整）：
```json
[
  {"column":"phone","method":"MASK","params":{"keepLeft":"3","keepRight":"4"}},
  {"column":"id_card","method":"MASK"},
  {"column":"account_no","method":"HASH","params":{"salt":"zgz-2026"}},
  {"column":"balance","method":"ROUND","params":{"digits":"0"}},
  {"column":"memo","method":"CLEAR"}
]
```

**保存**：点底部「确定」。同名策略会拒绝创建（提示"已存在"）。

### 2.3 编辑 / 删除策略
- **编辑**：列表「操作」列点「编辑」，表单回填后可改（仅创建人可编辑）。
- **删除**：点「删除」，确认后**软删**（列表不再显示；历史任务仍可追溯）。

## 3. Tab二：任务管理

> 任务 = 一次具体的抽样/脱敏执行。提交后产生一条记录，成功即生成**新的结果数据表**并注册，可挂载到项目、可（脱敏后）在页面查看。

### 3.1 顶部筛选与工具栏

- **状态下拉**：全部状态 / 待执行 / 执行中 / 成功 / 失败 / 已取消。
- **模式下拉**：全部 / 内置引擎 / 自定义代码。
- **搜索框**：任务 ID 或名称。
- **「提交任务」按钮**：打开提交表单（见 3.2）。
- **「结果数据集」按钮**：弹窗列出全部成功且含结果的任务（可**查看**、**挂载项目**）。

### 3.2 提交任务 —— 逐字段填写说明（点击「提交任务」）

> 以银行数据表为用例，**照抄以下值即可跑通第一个任务**。

**① 执行模式**（必填）
| 选项 | 说明 |
|---|---|
| `内置引擎 BUILTIN` | 后端 Java 进程内完成抽样/脱敏，**无需写代码**，同步出结果 |
| `自定义代码 CUSTOM` | 提交 Python 脚本，在**一次性 Kuscia 容器**中执行（隔离执行，见 5.6） |

- 示例：选 `内置引擎`。

**② 复用策略（可选）——下拉选择已有策略**
- 表单顶部的**「复用策略」下拉框**列出你已创建的策略（`策略名（类型）`），支持搜索。
- 选择某个策略后，页面**自动把该策略的抽样方法/抽样参数/脱敏列配置填入下方字段**——直接点「确定」即可**按策略对所选数据执行抽取（抽样）与脱敏**，无需手工重填。
- 也可以在此基础上**手工调整**下方字段（改动后按内联配置执行，即"内联覆盖策略"）。
- 清空下拉（点清除图标）则回到手动填写模式，下方配置清空。

**③ 源节点**（必填）
- 数据表所在节点。银行表所在节点为 **`dev-zgz`**。
- 权限要求：该表必须已授权到你的项目，或属于你所在机构（本实例 `dev-zgz`/`ctqkgaov` 满足）。

**④ 源数据表 ID**（必填）
- 银行表 ID：**`qpfcjppm`**。
- 填错或无权访问会提示 `GOV_NO_PERMISSION` / `GOV_NOT_FOUND`。

**⑤ 任务名称**（选填）
- 默认 `治理任务-<任务ID>`。可改，如 `银行数据手机号掩码`。

**⑥ 源数据预览**（强烈建议先做）
- 输入"预览行数"（1~100，默认 5），点**「预览前 N 行」**。
- 下方显示：源表名、行数、表头，以及前 N 行数据——**确认选对表和列**再提交（预览强制权限校验，越权会报错）。

**⑦ 抽样方法 / 抽样参数 (JSON) / 脱敏列配置 (JSON)**（仅「内置引擎」显示）
- 三个字段与"新建策略"的④⑤⑥完全一致，可直接内联填写（不引用策略时）；也可在②选择策略后由系统自动填充。
- 填写示例（100 行抽 30 行 + 手机号/身份证掩码）：
  - 抽样方法：`随机抽样 RANDOM`
  - 抽样参数：`{"count":30,"seed":42}`
  - 脱敏列配置：`[{"column":"phone","method":"MASK"},{"column":"id_card","method":"MASK"}]`
- 提交后任务按 `100 → 30` 行执行，脱敏列生效，查看结果可见掩码值。

**⑧ Python 脚本 / 脚本参数 (JSON)**（仅「自定义代码」显示）
- `Python 脚本`（必填）：标准 Python 3，约定三个命令行参数：`--input` 输入 CSV 路径、`--output` 输出 CSV 路径、`--params` 参数 JSON 字符串。**必须把处理后的结果写到 `--output`**。
- `脚本参数 (JSON)`（选填）：透传给脚本的 `--params`。
- 示例（最小可用脚本，过滤 `category == 'A'`）：
```python
import argparse, csv
ap = argparse.ArgumentParser()
ap.add_argument("--input"); ap.add_argument("--output"); ap.add_argument("--params")
a = ap.parse_args()
with open(a.input, newline="", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))
out = [r for r in rows if r.get("category") == "A"]
with open(a.output, "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=list(rows[0].keys()))
    w.writeheader(); w.writerows(out)
```
- 参数示例：`{"minAmount":1000}`（脚本内读取 `--params` 后 `json.loads` 使用）。

**提交**：点「确定」。任务进入 `待执行 → 执行中 → 成功/失败`。

### 3.3 任务列表、状态与操作

列表列：`任务`（名称+ID）、`模式`（内置引擎/自定义代码）、`源表`（节点/表ID）、`状态`（Tag 着色）、`行数`（源→结果）、`提交人`、`提交时间`、`操作`。

| 状态 | 标签颜色 | 说明 |
|---|---|---|
| 待执行 PENDING | 灰 | 排队中 |
| 执行中 RUNNING | 蓝（转） | 内置/自定义执行中 |
| 成功 SUCCEEDED | 绿 | 已生成结果数据表 |
| 失败 FAILED | 红 | 鼠标悬停状态标签可看错误原因 |
| 已取消 CANCELLED | 灰 | 已取消（平台停止 Kuscia Job） |

**操作列按钮**（按状态显示）：
- **取消**：`待执行/执行中` 可取消。
- **重试**：`失败` 可重试（retry_count +1，上限 3 次）。
- **查看结果**（本说明书新增）：`成功` 且有结果表时可用 → 在页面内直接查看结果数据（见 3.4）。
- **详情**：抽屉展示状态流转、源表/结果、血缘链、错误信息、自定义脚本全文。

### 3.4 查看结果 —— 结果数据展示（新增功能）

点成功任务「查看结果」或「结果数据集」弹窗里的「查看」，打开**结果数据抽屉**：

**① 顶部数据源/结果表信息栏**（表头即数据源）
```
数据源：gov_bank_sample（dev-zgz/qpfcjppm）  →  结果表：gov-gt-xxxx（dev-zgz/abcd1234）
[抽样：RANDOM]  [已脱敏]   记录数：100 → 5
```
- 「数据源」标签显示**源表名 + 所在节点/源表 ID**；
- 「结果表」标签显示**结果表名 + 所在节点/结果表 ID**；
- 抽样方法、是否已脱敏、记录数（源→结果）一目了然。

**② 数据区**（只有**已脱敏**的结果才会显示表格）
- 表格列 = 结果表表头（列名），行 = 脱敏后的数据，自动分页（每页 20 行）。
- 例：手机号列显示 `186****6835`、身份证 `110*******8251`、账号为 64 位哈希——**不再出现明文**。

**③ 未脱敏结果**（安全门禁）
- 若该结果是**纯抽样**（未做任何脱敏）或**自定义代码输出**（无法证明已脱敏），抽屉会显示黄色告警：
  「该结果未经脱敏，含真实数据，不予展示」——不会返回任何行数据。
- 这是刻意的安全设计：**只有脱敏后的结果才能被页面展示**，抽样子集含真实数据，不在展示范围。

> **✓ 实测记录（2026-08-19，dev 实例）**
>
> 用 `gov_bank_sample`（qpfcjppm）各提交了一个任务，结果展示两条路径均符合预期：
>
> | 任务 | 配置 | 结果 |
> |---|---|---|
> | `gt-0b11ed5d5242`（说明书示例：手机号身份证掩码+随机抽样5条） | RANDOM count=5 seed=42 + phone/id_card MASK + account_no HASH + balance ROUND + memo CLEAR | `已脱敏`，返回 5 行；样例值 `180****4681`、`110***********3185`、账号 64 位哈希、余额整数、备注空 |
> | `gt-16c13a2dee61`（说明书示例：纯随机抽样10条） | 仅 RANDOM count=10 seed=7，无脱敏 | 返回告警「该结果未经脱敏，含真实数据，不予展示」，无任何行数据 |

### 3.5 结果数据集 与 挂载项目
- 「结果数据集」弹窗列出所有成功任务（任务、结果表、行数、完成时间、操作）。
- **挂载项目**：选一个项目（下拉列出 P2P 项目）→ 确定。结果表以 `source=IMPORTED` 写入 `project_datatable`，即可在**项目详情「数据集」树**里看到该结果表，可在项目内消费、参与 SecretFlow 计算。（`source` 必须为 IMPORTED：项目数据集树仅按 `IMPORTED` 查询；早期版本误用 `CREATED` 导致挂载后项目内不显示，2026-08-20 已修复。）
- 同一结果重复挂同一项目会提示"已挂载"。

## 4. Tab三：血缘

- 两个输入框：**节点 ID**（留空 = 全部）、**数据表 ID**（可选）→ 点「查询」。
- 查询条件：**源表或结果表**任一命中即返回该血缘链。
- 列表：`血缘链`（源表 Tag → 目标结果表 Tag）、`操作类型`（SAMPLE / MASK / SAMPLE_MASK / CUSTOM）、`任务`、`创建人`、`时间`。
- 用例：在节点输入 `dev-zgz`，可看到 `gov_bank_sample → gov-gt-xxxx` 的全部抽样/脱敏链。

## 5. 六个实操示例（全部基于银行数据表）

> 每个示例都给出"表单填什么 + 预期结果 + 如何验证"。建议按顺序做。

### 示例 A：随机抽样 5 条（seed 可复现）

| 字段 | 填写 |
|---|---|
| 执行模式 | 内置引擎 |
| 源节点 / 源数据表 ID | `dev-zgz` / `qpfcjppm` |
| 抽样方法 | `随机抽样 RANDOM` |
| 抽样参数 | `{"count":5,"seed":42}` |
| 脱敏列配置 | 留空 |

- 预期：任务成功，`行数 100 → 5`；换一个任务再用同 seed，两次抽到**完全相同的 5 行**（可复现）。
- 验证：点「查看结果」→ 因未脱敏显示"不予展示"告警（这是**正确**行为）。

### 示例 B：手机号 + 身份证掩码（可查看结果）

| 字段 | 填写 |
|---|---|
| 执行模式 | 内置引擎 |
| 源节点 / 源数据表 ID | `dev-zgz` / `qpfcjppm` |
| 抽样方法 | （留空，全量 100 行） |
| 脱敏列配置 | `[{"column":"phone","method":"MASK"},{"column":"id_card","method":"MASK"}]` |

- 预期：成功，`100 → 100`；结果表 phone 列形如 `186****6835`，id_card `110*******8251`。
- 验证：点「查看结果」→ 顶部显示 `已脱敏`，表格中无明文手机号/身份证。

### 示例 C：分层抽样 + 类别替换

| 字段 | 填写 |
|---|---|
| 抽样方法 | `分层抽样 STRATIFIED` |
| 抽样参数 | `{"strataColumns":["category"],"count":1}` |
| 脱敏列配置 | `[{"column":"category","method":"REPLACE","params":{"mapping":"{\"A\":\"高风险\",\"B\":\"中风险\",\"C\":\"低风险\"}"}}]` |

- 预期：`100 → 3`（A/B/C 各 1 条），category 列变为中文风险等级。
- 验证：查看结果 → 3 行，每行 category 不同。

### 示例 D：整群抽样（按开户行整群）

| 字段 | 填写 |
|---|---|
| 抽样方法 | `整群抽样 CLUSTER` |
| 抽样参数 | `{"clusterColumn":"branch","count":1}` |
| 脱敏列配置 | `[{"column":"name","method":"REPLACE","params":{"value":"客户"}}]` |

- 预期：`100 → ~10`（随机选中一家开户行的全部记录），姓名列全为 `客户`。
- 验证：查看结果 → 所有行 branch 相同、name=`客户`。

### 示例 E：哈希 + 取整 + 空值清除（组合脱敏）

| 字段 | 填写 |
|---|---|
| 脱敏列配置 | `[{"column":"account_no","method":"HASH","params":{"salt":"bank-2026"}},{"column":"balance","method":"ROUND","params":{"digits":"0"}},{"column":"trans_amount","method":"ROUND","params":{"digits":"0"}},{"column":"memo","method":"CLEAR"}]` |

- 预期：账号变 64 位十六进制哈希（加盐不可逆）；余额/金额取整为 `467101`、`7433`；memo 全空。
- 验证：查看结果 → 无明文账号、无小数、memo 列空。

### 示例 F：自定义代码（一次性容器隔离执行）

| 字段 | 填写 |
|---|---|
| 执行模式 | `自定义代码 CUSTOM` |
| 源节点 / 源数据表 ID | `dev-zgz` / `qpfcjppm` |
| Python 脚本 | 见 §3.2 ⑦ 的最小脚本（过滤 `category == 'A'`） |
| 脚本参数 | `{"seed":1}` |

- 预期：任务走一次性 Kuscia 容器执行，成功 `100 → ~33`（A 类条数），血缘类型为 `CUSTOM`。
- 隔离说明：容器仅拿到输入子集（默认上限 5000 行/256KB，超限 `GOV_INPUT_TOO_LARGE`）、无外网、限 CPU/内存（默认 0.5 核/512MiB）、脚本超时会被 kill、跑完即删。结果同样注册为结果表。
- 验证：详情抽屉可见脚本全文与血缘；**查看结果**因无法证明已脱敏显示"不予展示"。

## 6. 权限与审计说明

- **谁能提交/查看**：任务/策略按**创建人**隔离，他人不可编辑、不可查看详情与结果；源表必须已授权到你项目，或属于你所在机构（`nodeId == 你的 ownerId`，或节点 `instId == 你的 ownerId`）。
- **预览门禁**：`预览前 N 行` 与结果展示都强制权限校验，越权返回 `GOV_NO_PERMISSION`。
- **展示门禁（新增）**：只有**已脱敏**的结果才会被页面展示；纯抽样/自定义输出一律不展示。
- **审计**：每次操作写入统一日志（`GOVERNANCE_*`）：策略创建/更新/删除、任务提交/成功/失败/取消/重试、结果挂载。左侧「统一日志」按 `GOVERNANCE` 检索即可查看。
- **血缘**：每次成功执行写入血缘链（源表 → 结果表），Tab三可查询。

## 7. 常见问题 FAQ

**Q1：任务成功但点「查看结果」显示"未经脱敏，不予展示"？**
- 正常。该任务是纯抽样（或自定义代码输出），结果含真实数据，页面按安全策略不展示。要做可展示的结果，请在任务里配置至少一条脱敏规则（MASK/REPLACE/HASH/ROUND/CLEAR）。

**Q2：提交任务报 `GOV_NO_PERMISSION`？**
- 源表未授权到你的项目，或不属于你所在机构。请先在数据管理中把表授权到项目，或确认节点归属。

**Q3：报 `GOV_NOT_FOUND` / 读不到物理文件？**
- 源表 ID 填错，或该表是旧版混合会话上传（物理目录与元数据不一致）。重新上传并创建数据表即可。

**Q4：自定义代码报 `GOV_INPUT_TOO_LARGE`？**
- 输入子集超过上限（默认 5000 行 / 256KB base64）。这是隔离设计——避免把全量真实数据带进容器。请减小输入或在脚本内做子集化。

**Q5：报 `GOV_STATE_CONFLICT`？**
- 状态流转非法，例如：取消已成功的任务、重试非失败任务、重复挂载同一结果。按提示调整。

**Q6：想删除结果表？**
- 当前治理结果表不支持直接删除（保持可追溯）。如需下线，在数据管理删除对应 DomainData 记录，血缘/任务记录保留。

**Q7：浏览器看不到刚提交的结果？**
- 点击右上角**刷新**按钮；结果在任务 `成功` 后立即生成。若长时间 `执行中`，看任务详情或统一日志确认是否有告警。
